# KeyboardShop — JavaScript Shop

Контрольная работа №4: «JavaScript: интерактивность, DOM, события, формы и валидация».

Автор: Ситников Александр Андреевич, группа ЭФБО-01-25.

- [Открыть сайт](https://titanik322.github.io/kr4-js-shop/)
- [Репозиторий](https://github.com/TitaNik322/kr4-js-shop)

Основа — собственный адаптивный HTML/CSS-магазин [КР №3](https://github.com/TitaNik322/kr3-responsive-shop), как рекомендовано в методических указаниях. Сохранены оформление, главный экран, навигация и адаптивные сетки. Каталог, страница товара, корзина и формы работают на чистом JavaScript; Bootstrap, React, Vue, сборщик и сторонние UI-библиотеки не используются.

## Запуск

```sh
git clone https://github.com/TitaNik322/kr4-js-shop.git
cd kr4-js-shop
python -m http.server 8774 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8774`. Устанавливать пакеты не требуется. Python используется только как необязательный HTTP-сервер; Python-файлов в проекте нет. Можно открыть `index.html` напрямую, но для общего хранилища между страницами рекомендуется HTTP.

## JavaScript-файлы

| Файл            | Назначение                                                                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `data.js`       | Массив восьми товаров и названия категорий.                                                                                                  |
| `main.js`       | Форматирование цен и скидок, безопасное создание текстовых узлов, навигация, страница товара, сохранение общего состояния, избранное и тема. |
| `catalog.js`    | Функции обработки массива, создание карточек, поиск, фильтры, сортировка, статистика и пагинация.                                            |
| `cart.js`       | Добавление, удаление, количество, расчёт суммы через `reduce` и промокод.                                                                    |
| `modal.js`      | Быстрый просмотр, открытие и закрытие `dialog`, управление клавиатурой и возвратом фокуса.                                                   |
| `validation.js` | Ошибки рядом с полями, итог заявки, подтверждение и имитация подготовки формы.                                                               |

Все скрипты подключены с `defer` в указанном порядке. Инициализация страниц выполняется после `DOMContentLoaded`, когда доступны DOM и функции остальных файлов. Код проверяет наличие элементов перед использованием.

Материалы: методические указания КР №4 и практические занятия №14–18. За основу взяты требования к чистому JavaScript, отдельным веткам и самостоятельным доработкам; функции React/Vue из постановки следующей работы не добавлялись.

## Данные и обязательная часть

В `products` восемь клавиатур. У каждой одинаковые свойства: `id`, `title`, `category`, `price`, `discountPercent`, `rating`, `isAvailable`, `image`, `description`, `format`, `connection`, `switches`. Идентификаторы уникальны, цены и рейтинги — числа, наличие — логическое значение. Категории `mechanical`, `optical`, `scissor` совпадают со значениями фильтра.

Цены, скидки, рейтинги и наличие заданы для демонстрации интерфейса и не являются актуальными коммерческими предложениями.

- Карточки на главной и в каталоге создаются из массива через `createElement`, `classList`, `textContent` и `append`.
- Поиск реагирует на `input`: убирает краевые пробелы и ищет часть названия без учёта регистра.
- Категория и сортировка реагируют на `change`. Поиск, категория, наличие, избранное и диапазон цены работают совместно.
- Сортировка по цене учитывает скидку товара; также доступны название и исходный порядок. `sort()` применяется к копии массива.
- `getProductTitles`, `getAvailableProducts`, `findProductById`, `calculateTotalPrice`, `countAvailableProducts`, `calculateAveragePrice` используются для подсказок, поиска и статистики.
- Выводятся количество результатов и пустое состояние с кнопкой сброса. На странице — до шести карточек, остальные доступны через пагинацию.
- `product.html?id=1` открывает модель из массива. Неизвестный `id` показывает «Товар не найден»; отсутствующую модель нельзя добавить в корзину.
- В форме проверяются обязательные поля, имя, email, телефон, товар, целое количество 1–10, адрес курьера и согласие. Ошибки связаны с полями через `aria-describedby` и `aria-invalid`, после исправления исчезают.

## Самостоятельные доработки

- Корзина: добавление из карточки, страницы товара и быстрого просмотра, изменение количества, удаление позиции, очистка и счётчик в шапке.
- Сумма корзины считается через `reduce`, включая количество и скидки товаров.
- Промокод `KEY10` даёт дополнительные 10% от стоимости товаров после их скидок. Повторное применение не суммирует скидку; промокод можно убрать. Суммы округляются до целых рублей.
- Избранное: кнопки с `aria-pressed`, счётчик, отдельный режим каталога и сохранение выбора.
- Пагинация, фильтр наличия, диапазон цены, подсказки названий, рейтинги, бейджи скидок и отключённые действия недоступных моделей.
- Быстрый просмотр с настоящими данными товара. Диалог закрывается кнопкой, Escape и нажатием вне окна; Tab остаётся внутри, после закрытия восстанавливается фокус.
- Светлая и тёмная темы с сохранением выбора.
- Оформление всех товаров из корзины или отдельной модели, подтверждение состава заявки и имитация подготовки с состоянием ожидания, защитой от повторного нажатия и очисткой формы.
- Самовывоз бесплатный. Курьер — 390 ₽, при стоимости товаров после всех скидок от 10 000 ₽ доставка бесплатная. Корзина не очищается после имитации: реальная покупка не совершается.

## Хранение и безопасный вывод

Ключ `localStorage`: `keyboardshop-kr4-v1`. Сохраняются только корзина вида `{ productId, quantity }`, идентификаторы избранного, допустимый промокод и тема. При восстановлении проверяются структура, существование товара, наличие и количество; повторы отбрасываются. Повреждённый JSON сбрасывается с сообщением. При запрете хранилища остаётся работа в памяти вкладки. Изменения синхронизируются между вкладками через `storage`.

Пользовательский ввод, названия товаров и сведения из хранилища не вставляются через `innerHTML`. Для вывода используются `textContent`, для полей — `value`, для разметки — DOM-элементы. Обработчики подключены через `addEventListener`, inline-обработчиков и `alert()` нет.

Backend, оплата и сетевой приём заявок не подключены. Подготовка формы имитируется локально с короткой задержкой; интерфейс прямо сообщает, что данные не отправлены. Имя, email, телефон, адрес и комментарий не записываются в хранилище и не выводятся в консоль.

## Как проверить

1. В каталоге введите `LOGITECH`, выберите категорию и сортировку. Для пустого результата введите `zzzz`, затем сбросьте условия. Проверьте вторую страницу.
2. Добавьте клавиатуру в избранное и корзину, измените количество. Обновите страницу и откройте вторую вкладку: счётчики сохраняются и синхронизируются.
3. В корзине примените `KEY10`, повторите применение, затем уберите код. Проверьте сумму и ограничения количества.
4. Перейдите к заявке из корзины. Отправьте пустую форму, затем проверьте неверные email и телефон, обязательный адрес курьера и согласие. Исправьте поля и подтвердите подготовку.
5. Откройте быстрый просмотр, проверьте Escape, Tab/Shift+Tab и возврат фокуса. Переключите тему и обновите страницу.
6. В DevTools → Sources поставьте breakpoint в `updateCatalog`: изменение поиска обновляет `catalogState`, после подготовки массива меняется DOM.

Проверки выполняются локально. В Chrome проверены сценарии каталога, избранного, корзины, промокода, двух вкладок, форм, безопасного вывода и восстановления повреждённого хранилища. Все шесть страниц проверены на ширинах 375, 768, 1024 и 1440 px; горизонтального переполнения и ошибок `pageerror` не обнаружено. Отдельно проверен запуск из чистого зафиксированного Git-снимка, без файлов рабочей папки и установленных пакетов: поиск → быстрый просмотр → корзина → заявка → завершение. Проверен breakpoint в `updateCatalog`. Тестовые пакеты, служебные снимки и тестовый workflow в репозитории не хранятся.
